# QA rulings

Product-owner decisions taken during QA round 1. Each entry records what was decided, why, and what it costs if the decision turns out wrong.

- **Ruling A (OQ-07, tournaments need an event registration).** Enrolling in a tournament and checking in to it requires the acting user to hold a non-cancelled registration (pending or confirmed) for the tournament's event. Enforced in `TournamentPolicy::enroll` / `checkIn` (so web, Discord `/tournament checkin` and Filament all share it) via `Tournaments\Support\EventRegistrationRequirement`, which only touches Registration through its public read-model `MyRegistration` and `RegistrationAvailability` (architecture baseline extended by the single edge `Tournaments -> Registration`). Orga bypasses. For team entries only the acting owner's registration is checked, not every roster member's. The tournament pages show "Melde dich zuerst zum Event an" with a link to the registration page while registration is open. *Why:* no-shows without a ticket distorted brackets and capacity. *Cost if wrong:* some legitimate guests (walk-ins registered late) are blocked until they register; relaxing means deleting the two policy clauses.
- **Ruling B (OQ-N7, withdraw own entry).** The owner of an entry (solo user, or the team owner/captain for a team entry; never a plain member) can withdraw while the tournament is in `enrollment` or `check_in` (`TournamentPolicy::withdraw`, route `tournaments.withdraw`, button with `confirm()` like registration cancel). `WithdrawEntry` now locks the parent tournament row first (same order as `EnrollSolo`/`StartTournament`), so a withdrawal racing a start either wins before seeding or is rejected as already started; it also clears `checked_in_at`. Withdrawn entries never count toward `max_entries`, so the slot is free immediately. `entryFor` (web) and the Discord check-in lookup now resolve the latest non-withdrawn entry, so withdrawing and re-enrolling works. *Why:* participants could not leave a bracket they would not play. *Cost if wrong:* late withdrawals before check-in close leave a gap an orga must fill by hand; the team "captain" is the team owner, there is no separate captain role.
- **Ruling C (OQ-N6, no self-cancel after check-in).** `RegistrationPolicy::cancel` lets a participant cancel their own registration only while `checked_in_at` is null and the event is not `finished`/`archived`; orga can always cancel. `RegistrationPolicy::cancelBlockedReason()` (`checked_in` | `event_over`) feeds both the policy and the registration page (`registration.canCancel` / `cancelBlockedReason`), where the cancel button is replaced by a short German explanation; a direct DELETE flashes the same message instead of a 403. Orga cancels through a new "Stornieren" row action on the event's registrations table (Filament had no cancel path before); `CancelRegistration` now also clears `checked_in_at` (the seat is still released by the `RegistrationCancelled` listener, event dispatch unchanged). *Why:* a checked-in guest vanishing from capacity/seating mid-LAN was unrecoverable and untraceable. *Cost if wrong:* a guest who leaves early must ask orga to cancel; clearing `checked_in_at` on cancel loses the arrival timestamp of cancelled registrations (re-register already reset it).
- **Ruling D (OQ-N2, timezone).** `app.timezone` stays UTC and no stored row changes. One display/input zone, `config('lanomat.timezone')` (env `APP_DISPLAY_TIMEZONE`, default `Europe/Berlin`), is used by: `EventDays` (arrival days, so an event starting 2026-11-20 00:30 Berlin = 23:30 UTC still offers "Fr, 20.11." first), Filament via `FilamentTimezone::set()` in `AppServiceProvider` (DateTimePickers read/write and `dateTime()` columns render in Berlin time; verified against the v5 `TimezoneManager`), schedule notification `H:i` times, and all Vue date formatting (`formatInstant`/`dayKey` in `resources/js/lib/datetime.ts`, zone from the shared Inertia prop `displayTimezone`). *Why:* UTC display/arrival days were one hour off around local midnight. *Cost if wrong:* a non-German deployment must set `APP_DISPLAY_TIMEZONE`; the arrival-plan day values already saved (plain `Y-m-d`) are unaffected. Not done / follow-up: Event::starts_at-based Discord/mail text that formats dates server-side does not exist yet (none found); any new server-side `format()` of an instant must go through `DisplayTimezone::local()`; `Event/Index.vue` formats only a year via the browser zone (immaterial).
- **Ruling E (F-01, tournament lifecycle in the admin).** A tournament is created as `draft` and the form has no status field; orga now moves it with Filament actions on the edit page (header) and the list (row), shared in `Tournaments\Filament\Support\TournamentLifecycleActions`, each delegating to an Action class that row-locks the tournament like `StartTournament`: `OpenTournamentEnrollment` (draft -> enrollment; refuses with a German list of what is missing: game, max. Anmeldungen (>= 2), and, unless `settings.require_checkin` is false, check-in opens/closes with closes after opens), `OpenCheckin` (enrollment -> check_in, now locked; the scheduler tick still does this automatically at `checkin_opens_at`), `StartTournament` (unchanged) and `ReopenToDraft` (enrollment|check_in -> draft only with zero non-withdrawn entries; the button is hidden otherwise). The edit page shows the status as a Filament badge under the title. No new states or transitions beyond draft <-> enrollment. Visibility is unchanged: draft tournaments are listed on the event's tournaments page like before (they only gate on the event's public visibility) but offer no sign-up. *Why:* participants could only enroll in `enrollment` and nothing in the admin ever set it. *Cost if wrong:* the scheduler tick can still move enrollment -> check_in on its own, so "Anmeldung schließen" can disappear without an orga click once entries exist or check-in opens.
- **Ruling F (team tournament enrollment).** The index/show enroll button for `team_size > 1` tournaments posted without `team_id` (404). The page now gets a `teamPicker` prop (`Tournaments\Support\TeamPicker`: the viewer's own teams, `eligible` = roster size equals `team_size`); the UI shows a Select + "Mit Team anmelden", disables non-eligible teams, and for users without a team shows a hint plus a link to create one. The enroll endpoint flashes a German error instead of a 404 when `team_id` is missing. Authorization is unchanged (`TeamPolicy::update` + `enroll` policy). *Cost if wrong:* team admins who are not the owner (orga bypass of `update` aside) cannot enroll a team they do not own; there is no captain role.
