Competition is where LANoMAT is loudest after the beamer: brackets, match reports, provisioned game
servers and stream overlays. The bracket engine is pure domain code under
`app/Modules/Tournaments/Domain/`, tested exhaustively before any UI touches it.

## The competition loop

1. **Game** — a cross-event catalogue entry (team size, optional Pelican egg, server presets).
2. **Tournament** — created as `draft`, announced, opened for enrollment, check-in, live, finished.
3. **Entry** — solo user or team, frozen into a `roster_snapshot` at start.
4. **Match** — generated by the bracket engine, played, reported, confirmed or disputed.
5. **Server** — optionally provisioned from a preset; readiness drives warmup and join links.
6. **Result** — bracket advances, Discord/voice rooms get created and cleaned up, stats accumulate.

`MatchReady` is the fan-out event: live bracket broadcast, in-app notifications, Discord channels,
Mumble/TeamSpeak rooms, web-voice rooms, a game server, presence. Each listener is registered only
when its module is enabled; the modules never call each other.

## What the bracket guarantees

| Format | Supported sizes |
|---|---|
| Single elimination | 2–64 |
| Double elimination | 2, 4, 6, 8, 16 |
| Round robin | Any enrolled count, tie-break by map/round score |

Byes are handled in the engine, not in the UI. A bracket exists only after the tournament is
started; before that the page shows slots, start time and rules. A `draft` tournament is invisible
to everyone but orga — the one rule is `Tournament::scopeVisibleTo`.
