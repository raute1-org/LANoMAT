Ridge Racer Type 4 is the LAN's browser arcade cabinet. One Node process serves the disc, the BIOS,
the soundtrack and an EmulatorJS front end; every player runs their own PCSX-Rearmed core inside the
page. The recipe (`resources/recipes/ridge-racer-type-4/`, slug `ridge-racer-type-4`, aliases `r4`,
`rr4`, `type 4`) installs the cabinet, places the user's own dump and starts it on port **8080**.

That makes it different from UT2004: there is no per-player install and no patch. The **host PC is the
cabinet** and must stay awake while people play. Everyone else needs only a browser on the LAN.

## Who this is for

| Role | What they do here |
|---|---|
| **Participant with a PC to spare** | Runs the cabinet for the room and shares the URL |
| **Participant** | Opens the LAN URL, plays R4, joins the 2P lounge |
| **Orga** | Puts the disc and BIOS on the file host, opens the firewall, keeps the host awake |

The cabinet is a web app: no controller driver, no DVD drive at play time. The disc and BIOS are
user-supplied; the recipe never downloads game data.

## What you need

| Requirement | Value / why |
|---|---|
| LANoMAT account + paired agent | The recipe and the plan come from the server ([agent guide](/docs/guides/install-the-agent)) |
| Ridge Racer Type 4 (USA) dump | `disc/r4.chd` (about **341 MB**) for the browser; CUE/BIN for the native path |
| Supported serial | **SLUS-00797** (NTSC-U); other regions may boot but are not the tested path |
| Node.js | **20 or newer** (`engines` in the cabinet repo) |
| Git + npm | For the clone and `_server` dependencies |
| BIOS (recommended) | `scph5501.bin` in `_server/game/bios/`; the cabinet ships **OpenBIOS** and boots without a retail dump |
| Host PC | Stays awake for the session; wired network preferred |
| Ports | **TCP 8080** for the cabinet, **TCP 3010** for the optional 2P relay |
| Disk | About 1 GB for the cabinet and its dependencies, plus the disc |

The recipe's requirements:

| Role | Label | Required | Match |
|---|---|---|---|
| `iso` | Ridge Racer Type 4 (USA) disc image | **yes** | `*ridge*racer*4*.bin`, `*R4*.cue`, `*ridge*racer*4*.chd`, `R4.chd` |
| `base` | PlayStation BIOS (scph5501.bin, NTSC-U) | yes, recommended | `scph5501.bin`, `scph*.bin` |
| `tool` | Node.js 20 or newer | **yes** | none — checked on the machine |
| `tool` | Ridge Racer 4 Recomp (native bundle) | no | `Ridge_Racer_4_Recomp_Windows*.zip`, `RidgeRacer4Recomp*.zip` |

The BIOS entry is marked required but its notes say the cabinet can boot with OpenBIOS/HLE. Treat a
real NTSC-U dump as the recommended baseline and a fully supported fallback as absent by design;
`?bios=hle` forces the built-in path.

## 1. Plan it like any other recipe

```bash
lanomat-agent plan r4 --os windows --event lan-raute-1
```

The plan resolves the disc, the BIOS and Node on the host. Expect `[LAN]` for the disc and BIOS if the
orga uploaded them; Node has no LAN file and is checked locally.

```text
LANoMAT install plan: Ridge Racer Type 4 (ridge-racer-type-4)
Version: 1.0.0   OS: windows
Install dir: C:\Games\RidgeRacer4

Files:
  [LAN] r4.chd · 341 MB
  [LAN] scph5501.bin
Steps:
  1. Clone the cabinet and install its Node dependencies (Windows)
  2. Place the disc image in disc/
  3. Add the PlayStation BIOS (or use the bundled OpenBIOS)
  4. Start the cabinet and open the LAN URL (Windows)
  5. Check the cabinet before the LAN night
All required files are available.
```

`--json` gives the raw plan; `--dry-run` on `install` prints the commands without running them.
A missing disc is a hard stop; a missing BIOS is not, because of OpenBIOS.

## 2. Install the cabinet

```bash
lanomat-agent install r4 --os windows --event lan-raute-1
```

The recipe clones the repository into the target and installs the `_server` dependencies. The
commands are repeatable — re-running `npm install` on an existing checkout is safe.

```powershell
git clone https://github.com/reneil1337/riiiiiiiiiidge-raaaaaaaaaaaaceer.git "{{target}}"
npm --prefix "{{target}}/_server" install
```

Linux is the same two commands with `bash`; the Windows `.bat` helpers are not used there.

The repository is a Node 20+ Express app. There is **no build step** for the browser cabinet: the
files in `_server/` are served as they are. Verification is `_server/package.json`.

## 3. Place the disc

Put the user's dump in `{{target}}/disc/`.

| Path | What it is |
|---|---|
| `disc/r4.chd` | The browser deck's disc (about 341 MB) |
| `disc/*.cue` + `*.bin` | The native recomp's pair; convert to CHD for the browser if needed |

```powershell
New-Item -ItemType Directory -Force -Path "{{target}}/disc" | Out-Null
Copy-Item -Path "{{downloads}}/r4.chd" -Destination "{{target}}/disc/r4.chd" -Force
```

If the matched file has another name, rename it to `r4.chd` **in the downloads folder** before the
copy — or adjust the command. Do not rename the tracks inside a CUE. The recipe verifies
`{{target}}/disc/r4.chd`.

**Dump format.** `.bin`/`.cue` is the raw disc; `.chd` is the compressed archival format the browser
path expects. Keep the CUE/BIN pair together and unmodified for the native recomp. A PAL or NTSC-J
dump is not the tested path; SLUS-00797 is.

## 4. Add the BIOS (or use OpenBIOS)

```powershell
New-Item -ItemType Directory -Force -Path "{{target}}/_server/game/bios" | Out-Null
Copy-Item -Path "{{downloads}}/scph5501.bin" -Destination "{{target}}/_server/game/bios/scph5501.bin" -Force
```

The cabinet ships `openbios.bin`, so this step can be skipped. A retail `scph5501.bin` is the
recommended baseline for compatibility. Select it in the deck with
`?bios=/bios/scph5501.bin`; `?bios=hle` forces the built-in HLE path.

**Never download a BIOS for the user.** A BIOS is a user-supplied dump, exactly like the disc. The
recipe matches `scph5501.bin` or `scph*.bin` from the LAN file host.

## 5. Start the cabinet

**Windows:** run `_server\start-test.bat` in its own window.

```powershell
Start-Process "{{target}}/_server/start-test.bat"
```

**Linux:** start the server directly.

```bash
node "{{target}}/_server/src/server.js"
# or
npm --prefix "{{target}}/_server" start
```

Then open:

| Where | URL |
|---|---|
| On the host | `http://localhost:8080/` |
| On any LAN device | `http://<host-lan-ip>:8080/` |
| Field manual (served by the cabinet) | `http://<host-lan-ip>:8080/docs` |
| R4 directly | `http://<host-lan-ip>:8080/play?game=r4` |
| Race Day | `http://<host-lan-ip>:8080/race-day` |
| 2P lounge | `http://<host-lan-ip>:8080/multiplayer` |

Leave the window open. The host PC is the cabinet; a closed terminal or a sleeping PC ends the
session. On Windows, `firewall.bat` opens the firewall for LAN devices.

| Port | Purpose |
|---|---|
| TCP 8080 | The cabinet and the EmulatorJS front end |
| TCP 3010 | The optional netplay relay used by the 2P lounge |

## 6. Play: solo, 2P, Race Day

| Mode | Where | What it does |
|---|---|---|
| Solo | `/play?game=r4` | One player, one browser tab, full speed |
| 2P VS Battle | `/multiplayer` | Split-screen VS on R4: room code, DISC selector, teams, READY |
| Race Day | `/race-day` | Up to 50 drivers on one shared clock (MVP target) |

**2P lounge.** One player hosts a room and shares the code; the second joins from another device. The
relay carries the session, so both tabs stay in sync. Two gamepads (or one pad and the keyboard) are
enough; the browser exposes them through the Gamepad API.

**Race Day.** The 50-seat figure is an **MVP target verified with synthetic WebSocket clients**, not
with 50 humans. The guest stream carries video only — expect no guest audio. Players with a weak
laptop should close other tabs; each browser runs its own emulator core.

The same repository also serves **Rage Racer** and **Ridge Racer (1994)** when their discs are present;
the recipe only matches R4.

## 7. Optional: the native Windows recomp

The browser cabinet is the primary LAN path. The native recomp
(`https://github.com/omegakatana92/RidgeRacer4Recomp`, v1.0.0) is a Windows-only alternative that
reads the CUE/BIN pair.

```powershell
Expand-Archive -Path "{{downloads}}/Ridge_Racer_4_Recomp_Windows.zip" -DestinationPath "{{target}}/RidgeRacer4Recomp" -Force
& "{{target}}/RidgeRacer4Recomp/launcher/ridgeRacer4.bat"
```

- It reads `{{target}}/disc/` and expects the USA serial SLUS-00797.
- It bundles OpenBIOS; the launcher lets you pick the pad and the BIOS.
- Set `settings.toml` `[video] fullscreen = 0` until Borderless mode has been verified. Exclusive
  fullscreen can switch the desktop to 1024x768.
- Run **one** native instance at a time. Two instances fight over the same disc and settings.
- Verification: `RidgeRacer4Recomp/Ridge_Racer_4_Recompiled.exe`.

The recipe's metadata names the recomp as the launch target
(`RidgeRacer4Recomp\Ridge_Racer_4_Recompiled.exe`) and the cabinet as `play_url`
(`http://localhost:8080/`). The game page's **Starten** button opens the web URL when it exists.

## 8. Verify before the LAN night

| Check | Command / result |
|---|---|
| Cabinet answers | `curl -fsS http://localhost:8080/` |
| R4 boots | `/play?game=r4`; intro plays, car select accepts input |
| Disc correct | Car select and tracks match R4, not another Ridge title |
| BIOS choice | Retail dump or `?bios=hle`; no BIOS error screen |
| 2P transport | `node _server/verify-mp.mjs` on the host |
| Race Day | `/race-day` opens; a second device sees the room |
| QA state | Read `_server/PLAY-QA.md` before promising a mode |
| Native (optional) | Launcher starts, disc verified, one instance only |

`lanomat-agent plan r4` re-checks file presence; it does not test the running server. The
`verify` steps in the plan use `curl` for the cabinet and `file_exists` for the disc and BIOS.

## The four states of the cabinet

| State | What you see | What it means |
|---|---|---|
| **Normal** | `http://localhost:8080/` serves the deck; R4 boots | Disc, BIOS and server are in place |
| **Empty** | Deck loads but no game boots; disc missing in `_server` | `disc/r4.chd` absent or under another name |
| **Loading** | The emulator core downloads, then the intro | First load caches the core in the browser; later loads are faster |
| **Error** | BIOS screen, black canvas, or connection refused | BIOS path wrong, disc unreadable, or the Node process is not running |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `EADDRINUSE :8080` | Another process holds the port | Stop it, or change the cabinet's port and tell players the new URL |
| Connection refused from another device | Server bound to localhost, or firewall closed | Start with the LAN default; run `firewall.bat`; allow TCP 8080 |
| 2P lounge cannot connect | Relay port blocked | Allow **TCP 3010** on the host firewall |
| Black screen after boot | Missing/unsupported BIOS or bad dump | Try `?bios=hle`; re-copy a known-good `r4.chd` |
| "No disc" / wrong game | Dump is not R4, or file name differs | Use SLUS-00797; place it as `disc/r4.chd` |
| CUE/BIN not recognised | Tracks renamed or split | Keep the original CUE/BIN pair; do not edit track names |
| Cabinet loads, no sound | Guest stream is video-only in Race Day; solo audio needs a user gesture | Click the canvas once; check the host's audio device |
| Race Day lags with many players | Each browser runs its own core; host relay saturated | Lower the player count; wire the host; close other tabs |
| Native recomp switches resolution | Exclusive fullscreen at 1024x768 | `settings.toml` → `[video] fullscreen = 0` |
| Native recomp finds no disc | It reads `disc/` as CUE/BIN | Keep the CUE/BIN pair in `{{target}}/disc/` |
| `npm install` fails | Node older than 20 | Install the current LTS; re-run `npm --prefix _server install` |
| Host sleeps mid-session | Power settings | Disable sleep on the host for the event; keep it on wired power |
| Cabinet URL works on host only | Players use `localhost` | Share `http://<host-lan-ip>:8080/` |

## Checklist

- [ ] Node 20+ on the host; `_server/package.json` exists.
- [ ] `disc/r4.chd` in place (or CUE/BIN for the native path); serial SLUS-00797.
- [ ] BIOS at `_server/game/bios/scph5501.bin`, or OpenBIOS accepted deliberately.
- [ ] Cabinet starts and answers on `http://localhost:8080/`.
- [ ] LAN URL works from a second device.
- [ ] TCP 8080 open; TCP 3010 open if the 2P lounge is offered.
- [ ] `node _server/verify-mp.mjs` passes; `PLAY-QA.md` read.
- [ ] Host sleep disabled; power and network cables secured.
- [ ] 2P room code tested with two devices.
- [ ] Race Day limit communicated (50 = MVP target, video-only guests).
- [ ] Optional: native recomp installed, one instance, fullscreen setting checked.
